# School Permissions Push Test — ملفات اختبار فقط

## الأمان
- هذه نسخة اختبارية من واجهة HTML السابقة، وليست نشرًا جاهزًا للإنتاج.
- تم استبدال رابط Google Apps Script الأصلي بعنصر نائب `PASTE_TEST_APPS_SCRIPT_WEB_APP_URL_HERE` حتى لا تتصل الواجهة بالنظام الأصلي.
- تم حذف أرقام الهواتف الثابتة من نسخة الاختبار.
- لا ترفع بيانات الموظفين أو كلمات المرور أو مفاتيح الخدمة الخاصة إلى GitHub.
- لا تستبدل ملفات النظام الأصلي بهذه الملفات.

## الملفات
- `index.html`: واجهة الاختبار المشتقة من نسخة HTML التي كانت متاحة في المحادثة، مع قسم اختبار إشعارات.
- `firebase-messaging-sw.js`: service worker لاستقبال إشعارات FCM في الخلفية.
- `manifest.json`: تعريف تطبيق ويب بسيط.

## قبل الاختبار
1. في `index.html` و`firebase-messaging-sw.js` استبدل القيم `REPLACE_WITH_*` بقيم Firebase Web App config من مشروع الاختبار فقط.
2. ضع المفتاح العام VAPID في `index.html` مكان `REPLACE_WITH_PUBLIC_VAPID_KEY`.
3. لا تضع مفتاح خدمة Firebase Admin أو أي مفتاح خاص في ملفات المتصفح.
4. اربط `API_URL` برابط نشر Web App الخاص بمشروع Apps Script التجريبي فقط بعد نشره. لا تضع رابط الإنتاج.
5. ارفع الملفات إلى جذر مستودع الاختبار ثم فعّل GitHub Pages. يجب أن يعمل الموقع عبر HTTPS.
6. أضف أيقونتين `icons/icon-192.png` و`icons/icon-512.png` قبل اعتماد manifest كتطبيق قابل للتثبيت، أو عدّل مسارات الأيقونات إلى ملفات موجودة.
7. افتح الموقع على الجهاز، واضغط «تفعيل إشعارات هذا الجهاز». بعد إنشاء الرمز، استخدم Firebase Console لإرسال إشعار اختبار إلى رمز الجهاز.

## حدود هذه المرحلة
- هذه الملفات تهيئ استقبال إشعارات الويب وتسمح باستخراج رمز جهاز للاختبار.
- لم يُضف بعد تخزين الرموز على الخادم، أو إرسال إشعارات تلقائية حسب تسلسل الموافقات. يتطلب ذلك تعديلًا منفصلًا وآمنًا في Apps Script التجريبي وربطه بحسابات المستلمين.
- قد تختلف الخطوات على iPhone؛ إشعارات الويب تتطلب إصدار iOS/Safari مدعومًا وإضافة الموقع إلى الشاشة الرئيسية بحسب دعم Apple.
